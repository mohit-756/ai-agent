# SpendWise - AI-Powered Personal Finance & Peer Ledger

SpendWise is a minimalist, high-performance personal finance dashboard. It features smart budgeting, AI expense coaching, evolutionary insights, a client-side **Peer Ledger** for money tracking, and a **Vercel Serverless WhatsApp Bot Webhook** that uses Gemini AI for text parsing and receipt OCR scanning.

---

## 🚀 How it Works

### 👥 Peer Ledger (Giving / Taking Money)
The Peer Ledger allows you to keep track of loans, splits, and debts with friends without bloating your formal categories.
1. **Adding Records**: Go to the **Peer Ledger** tab and select whether you **Lent** or **Borrowed** money, enter the friend's name, amount, date, and description.
2. **Outstanding Balances**: Outstanding amounts are grouped by person. If Rohit owes you ₹1,200 for ticket splits and ₹800 for lunch, they are aggregated under Rohit's card as "Owed to Me".
3. **Relative Reminders & Due Dates**:
   - Set a due date for any transaction.
   - The UI automatically shows badges like `Overdue by 2 days` or `Due in 4 days`.
   - Click the **WhatsApp Icon** next to any pending balance to generate a polite, pre-filled reminder template to message them.
4. **Paybacks**: When someone returns part of or all the money, click **Log Payback**. You can enter the payback date and amount (supporting partial paybacks). SpendWise updates the outstanding balance dynamically and archives it to settled once the balance hits zero.
5. **AI Assistant Integration**: You can type questions in the **AI Coach** tab like *"who owes me money?"* or *"what is my net balance?"* and the assistant will query your Peer records to summarize active debts.

## 🛠️ Backend Setup (Supabase & Vercel)

If you run the app locally, it functions entirely offline using **LocalStorage** as a fallback. To sync transactions, utilize the WhatsApp Bot, or deploy to production, set up the backend components as described below:

### 1. Supabase Database Schema
You need a table and a storage bucket in your Supabase project.

#### Database Table: `expenses`
Run this SQL in your Supabase SQL Editor:
```sql
create table expenses (
  id bigint generated by default as identity primary key,
  created_at timestamp with time zone default timezone('utc'::text, now()) not null,
  amount numeric not null,
  category text not null,
  description text not null,
  merchant text,
  paymentmethod text default 'UPI',
  date date default current_date not null,
  notes text,
  source text default 'manual',
  receipt_url text
);
```

#### Database Table: `peer_records` (Optional)
Run this SQL if you want the live WhatsApp Bot to sync peer records directly to your database instead of client LocalStorage:
```sql
create table peer_records (
  id bigint generated by default as identity primary key,
  created_at timestamp with time zone default timezone('utc'::text, now()) not null,
  name text not null,
  amount numeric not null,
  original_amount numeric not null,
  type text not null, -- 'lent' or 'borrowed'
  description text,
  date date default current_date not null,
  due_date date,
  status text default 'pending' -- 'pending' or 'settled'
);
```

#### Storage Bucket: `receipts`
1. Go to **Storage** in your Supabase dashboard.
2. Create a new bucket named **`receipts`**.
3. Set the bucket access to **Public** (so the app can retrieve public URLs for image previews).

> [!NOTE]
> The WhatsApp Bot parses sentences like *"Lent ₹500 to Sneha for dinner split due next week"*.
> - If the `peer_records` table exists in Supabase, the bot will insert it there.
> - If that table does not exist, it will fallback to saving it inside your `expenses` table categorized under `Others` and mention it in the reply message.
> - In local development, the simulator saves records directly to your browser's local `localStorage`!

### 2. Vercel Backend Environment Variables
The serverless WhatsApp webhook `/api/whatsapp.ts` processes incoming texts and images. Deploy the project to Vercel and configure these Environment Variables:

| Variable | Scope | Description |
| :--- | :--- | :--- |
| `SUPABASE_URL` | Webhook (Vercel) | Your Supabase project URL |
| `SUPABASE_KEY` | Webhook (Vercel) | Your Supabase service role secret API key (needed to bypass RLS for bot writes) |
| `GEMINI_API_KEY` | Webhook (Vercel) | Your Google Gemini API Key (obtained from Google AI Studio) |
| `WHATSAPP_TOKEN` | Webhook (Vercel) | Meta Cloud API System User Access Token |
| `VERIFY_TOKEN` | Webhook (Vercel) | Custom secret token (e.g. `my_secret_token_123`) to authorize webhook web handshake |
| `VITE_SUPABASE_URL` | Frontend (Client) | Public project URL for client-side queries |
| `VITE_SUPABASE_ANON_KEY`| Frontend (Client) | Public anonymous key for client-side queries |

## 🤖 WhatsApp Bot Webhook Flow
When you send a message to your configured WhatsApp Business number:
1. **Text Messages**: The webhook parses strings like *"Spent ₹349 on Swiggy lunch"* using natural language matching, determines the category (`Food & Dining`), sets payment method (`UPI`), and saves it to Supabase.
2. **Image Messages (Receipts/Bills)**:
   - The webhook downloads the photo buffer from Meta servers.
   - It uploads the image directly to your Supabase `receipts` bucket.
   - It streams the image payload to Google Gemini AI which extracts details (Amount, Merchant, Category, Payment Method, Description) using structured JSON OCR.
   - The parsed transaction is saved directly to your Supabase database.
   - A success reply containing the parsed receipt summary is sent back to your WhatsApp thread.
